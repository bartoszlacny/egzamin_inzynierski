Programowanie obiektowe 2 (Python)

1. Klasy i obiekty w Pythonie — podstawy

Definicja klasy i inicjalizator

class Osoba:
    def __init__(self, imie, wiek):   # inicjalizator — wywoływany przy tworzeniu obiektu
        self.imie = imie               # atrybut instancyjny
        self.wiek = wiek

    def przywitaj(self):               # metoda instancyjna — pierwszy parametr to self
        print(f"Cześć, jestem {self.imie}")

o1 = Osoba("Jan", 25)   # tworzenie instancji — Python wywołuje __new__, potem __init__
o1.przywitaj()

self — jawne odwołanie do instancji

W Pythonie self nie jest słowem kluczowym (to tylko konwencja nazewnicza) — każda metoda instancyjna otrzymuje odwołanie do obiektu, na którym została wywołana, jako pierwszy, jawny parametr — inaczej niż w C++/Javie, gdzie this jest niejawne.

Wszystko w Pythonie jest obiektem

Liczby, stringi, funkcje, klasy same są obiektami (instancjami swoich klas) — type(5) zwraca <class 'int'>, type(Osoba) zwraca <class 'type'> (patrz metaklasy, punkt 5).

Reprezentacja obiektów — __str__ i __repr__

class Punkt:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __str__(self):     # reprezentacja "czytelna dla człowieka" — print(obj), str(obj)
        return f"({self.x}, {self.y})"

    def __repr__(self):    # reprezentacja "dla programisty" — repr(obj), w konsoli interaktywnej
        return f"Punkt(x={self.x}, y={self.y})"

p = Punkt(1, 2)
print(p)        # (1, 2)          — używa __str__
print([p])      # [Punkt(x=1, y=2)] — elementy listy używają __repr__!
Zasada: __repr__ powinien (idealnie) dać się skopiować i wkleić jako poprawny kod odtwarzający obiekt; __str__ to swobodniejszy, czytelny opis. Jeśli zdefiniujesz tylko __repr__, Python użyje go też jako fallback dla __str__.

Atrybuty dynamiczne

W przeciwieństwie do Javy/C++, obiektom Pythona można dodawać atrybuty po utworzeniu, nawet nieprzewidziane w __init__ (o ile klasa nie używa __slots__):

o1.email = "jan@example.com"   # dodanie zupełnie nowego atrybutu w locie

2. Atrybuty i metody klasowe, właściwości, przeciążanie operatorów

Atrybut klasowy vs instancyjny

class Licznik:
    ilosc = 0            # atrybut KLASOWY — współdzielony przez wszystkie instancje

    def __init__(self):
        Licznik.ilosc += 1   # modyfikacja przez nazwę klasy

a = Licznik()
b = Licznik()
print(Licznik.ilosc)   # 2
Pułapka: self.ilosc += 1 (zamiast Licznik.ilosc += 1) stworzyłoby nowy atrybut instancyjny "przesłaniający" klasowy dla tego jednego obiektu, nie modyfikując wspólnej wartości — częsty błąd początkujących.

Metody statyczne i klasowe

class Matematyka:
    @staticmethod
    def kwadrat(x):          # brak dostępu do self/cls — jak zwykła funkcja "przypisana" do klasy
        return x * x

    @classmethod
    def z_stringa(cls, s):    # otrzymuje klasę (cls), często jako alternatywny konstruktor
        return cls(int(s))

Matematyka.kwadrat(5)   # 25

Właściwości (@property)

class Kolo:
    def __init__(self, r):
        self._r = r

    @property
    def promien(self):          # getter — dostęp jak do zwykłego pola: obj.promien
        return self._r

    @promien.setter
    def promien(self, wartosc):  # setter — z możliwością walidacji
        if wartosc < 0:
            raise ValueError("Promień nie może być ujemny")
        self._r = wartosc

    @property
    def pole(self):               # właściwość tylko do odczytu (brak settera)
        return 3.14159 * self._r**2

k = Kolo(5)
k.promien = 10       # wywołuje setter, z walidacją
print(k.pole)        # wywołuje getter — bez nawiasów wywołania!

@property pozwala "ukryć" logikę gettera/settera za składnią zwykłego dostępu do pola — enkapsulacja bez konieczności pisania jawnych getX()/setX() jak w Javie/C++.

Przeciążanie operatorów — metody magiczne (dunder)

class Wektor:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, inny):        # obj1 + obj2
        return Wektor(self.x+inny.x, self.y+inny.y)

    def __eq__(self, inny):          # obj1 == obj2
        return self.x==inny.x and self.y==inny.y

    def __len__(self):               # len(obj)
        return int((self.x**2+self.y**2)**0.5)

w1, w2 = Wektor(1,2), Wektor(3,4)
w3 = w1 + w2      # wywołuje __add__

3. Iterowalność, iteratory i elementy funkcyjne

Protokół iteracji

  • iterowalny (iterable) — obiekt implementujący __iter__, zwracający iterator
  • iterator — obiekt implementujący __next__ (zwraca kolejny element albo rzuca StopIteration), zwykle też __iter__ zwracające self
class Zakres:
    def __init__(self, start, koniec):
        self.aktualny = start
        self.koniec = koniec

    def __iter__(self):
        return self                    # sam siebie jest iteratorem

    def __next__(self):
        if self.aktualny >= self.koniec:
            raise StopIteration
        wartosc = self.aktualny
        self.aktualny += 1
        return wartosc

for x in Zakres(1, 5):    # 1 2 3 4
    print(x)

Generatory jako łatwiejszy sposób pisania iteratorów

def zakres_gen(start, koniec):
    aktualny = start
    while aktualny < koniec:
        yield aktualny
        aktualny += 1

yield automatycznie tworzy obiekt implementujący cały protokół iteracji — dużo mniej kodu niż ręczne pisanie __iter__/__next__ (patrz też przedmiot Języki skryptowe).

Funkcje wyższego rzędu

Funkcje przyjmujące inne funkcje jako argumenty lub zwracające funkcje — możliwe, bo w Pythonie funkcje są obiektami pierwszej klasy.

Lambda — funkcje anonimowe

kwadrat = lambda x: x**2
dodaj = lambda a, b: a + b

Ograniczenie: ciało lambdy to jedno wyrażenie (nie może zawierać wielu instrukcji, pętli itd.) — do bardziej złożonej logiki potrzeba zwykłej funkcji def.

map, filter, reduce

from functools import reduce

liczby = [1, 2, 3, 4, 5]

kwadraty = list(map(lambda x: x**2, liczby))          # [1,4,9,16,25]
parzyste = list(filter(lambda x: x%2==0, liczby))     # [2,4]
suma = reduce(lambda a,b: a+b, liczby)                 # 15 (kumulatywnie: ((((1+2)+3)+4)+5))
FunkcjaDziałanie
map(f, iterable)zastosuj f do każdego elementu — zwraca nowy iterator wyników
filter(f, iterable)zachowaj tylko elementy, dla których f zwraca True
reduce(f, iterable)"zwiń" sekwencję do jednej wartości, stosując f kumulatywnie parami
W praktyce w "pythonicznym" stylu listy składane (list comprehensions, patrz przedmiot Języki skryptowe) często zastępują map/filter — [x**2 for x in liczby if x%2==0] bywa uznawane za bardziej czytelne niż zagnieżdżone map(filter(...)).

4. Relacje między klasami i zaawansowane dziedziczenie

Dziedziczenie i super()

class Zwierze:
    def __init__(self, imie):
        self.imie = imie
    def opis(self):
        return f"Zwierzę o imieniu {self.imie}"

class Pies(Zwierze):
    def __init__(self, imie, rasa):
        super().__init__(imie)   # wywołanie konstruktora klasy bazowej
        self.rasa = rasa
    def opis(self):
        return super().opis() + f", rasa {self.rasa}"   # rozszerzenie zachowania bazowego

Wielodziedziczenie i MRO (Method Resolution Order)

Python zezwala na dziedziczenie po wielu klasach naraz — kolejność przeszukiwania metod przy takim dziedziczeniu określa MRO (algorytm C3 linearization), sprawdzalne przez KlasaX.__mro__.

class A: 
    def kto(self): return "A"
class B(A): 
    def kto(self): return "B"
class C(A): 
    def kto(self): return "C"
class D(B, C): pass

D().kto()          # "B" — bo B jest pierwsze w MRO
print(D.__mro__)   # (D, B, C, A, object)

Agregacja vs kompozycja

AgregacjaKompozycja
Relacja"ma" (has-a), słabsza"jest zbudowany z" (part-of), silniejsza
Czas życia częściniezależny od całości (część może istnieć bez całości)zależny — usunięcie "całości" usuwa/dezaktualizuje "część"
PrzykładUniwersytet ma Studentów (studenci istnieją niezależnie)Dom składa się z Pokoi (pokój bez domu nie ma sensu)
# kompozycja — Silnik tworzony i "żyje" wewnątrz Samochodu
class Silnik:
    def __init__(self, moc): self.moc = moc

class Samochod:
    def __init__(self, moc_silnika):
        self.silnik = Silnik(moc_silnika)   # Samochod "posiada" Silnik jako część siebie

# agregacja — Student istnieje niezależnie, Uniwersytet tylko go referencjuje
class Uniwersytet:
    def __init__(self):
        self.studenci = []
    def zapisz(self, student):
        self.studenci.append(student)   # student przekazany "z zewnątrz", nie tworzony wewnątrz

Protokoły (duck typing)

Python nie wymaga formalnej implementacji interfejsu, żeby obiekt "pasował" do oczekiwanego zachowania — jeśli obiekt ma metody, których oczekujemy (np. __len__, __iter__), to "wystarczy", niezależnie od jego formalnej hierarchii klas ("if it walks like a duck and quacks like a duck...").

Abstrakcyjne klasy bazowe (abc)

from abc import ABC, abstractmethod

class Ksztalt(ABC):
    @abstractmethod
    def pole(self):
        pass

class Kwadrat(Ksztalt):
    def __init__(self, bok): self.bok = bok
    def pole(self):
        return self.bok ** 2

# Ksztalt()      # BŁĄD: nie można tworzyć instancji klasy abstrakcyjnej
k = Kwadrat(5)    # OK — zaimplementowano pole()

Moduł abc (Abstract Base Classes) wymusza formalnie to, co przy "duck typing" jest tylko konwencją — analogicznie do klas abstrakcyjnych w C++/Javie.

5. Deskryptory i metaklasy

Deskryptory

Obiekty implementujące protokół deskryptora — kontrolują, co się dzieje przy odczycie/zapisie atrybutu klasy, do której są przypisane. Metody: __get__, __set__, __delete__.

Typ deskryptoraImplementuje
Deskryptor danych (data descriptor)__get__ i (__set__ lub __delete__) — ma priorytet nad słownikiem instancji
Deskryptor niebędący danymi (non-data)tylko __get__ — np. zwykłe metody i @property bez settera
class Dodatnia:
    def __set_name__(self, owner, name):
        self.name = "_" + name

    def __get__(self, instance, owner):
        return getattr(instance, self.name)

    def __set__(self, instance, value):
        if value < 0:
            raise ValueError(f"{self.name} musi być dodatnia")
        setattr(instance, self.name, value)

class Produkt:
    cena = Dodatnia()    # deskryptor stosowany do każdej instancji Produkt

    def __init__(self, cena):
        self.cena = cena   # wywołuje Dodatnia.__set__

p = Produkt(100)
p.cena = -5   # ValueError!

@property (patrz punkt 2) to w rzeczywistości "cukier syntaktyczny" zaimplementowany właśnie za pomocą deskryptorów — deskryptory dają bardziej ogólny, wielokrotnie używalny mechanizm (jeden deskryptor można przypisać do wielu atrybutów/klas, w odróżnieniu od @property, które definiuje się per-atrybut).

Mechanizm dostępu do atrybutów — kolejność wyszukiwania

Przy obj.atrybut, Python sprawdza (w skrócie): deskryptory danych w klasie → słownik instancji (obj.__dict__) → deskryptory niebędące danymi/zwykłe atrybuty klasy → __getattr__ (jeśli zdefiniowane, jako "ostatnia szansa" gdy nic innego nie znaleziono).

Metaklasy

"Klasa klasy" — obiekt, który tworzy/definiuje inne klasy, tak jak klasa tworzy obiekty. Domyślną metaklasą wszystkich klas w Pythonie jest type.

class Osoba:
    pass

print(type(Osoba))        # <class 'type'> — Osoba jest instancją type!
print(type(Osoba()))      # <class '__main__.Osoba'> — obiekt jest instancją Osoba

Własna metaklasa

class MojaMetaklasa(type):
    def __new__(cls, nazwa, bazy, atrybuty):
        atrybuty['wersja'] = "1.0"    # automatyczne dodanie atrybutu do KAŻDEJ klasy używającej tej metaklasy
        return super().__new__(cls, nazwa, bazy, atrybuty)

class MojaKlasa(metaclass=MojaMetaklasa):
    pass

print(MojaKlasa.wersja)   # "1.0" — dodane automatycznie przez metaklasę

Zastosowania metaklas

  • automatyczna rejestracja podklas (np. wzorzec "plugin" — każda nowa podklasa sama się "zapisuje" do rejestru)
  • walidacja struktury klasy w momencie jej definicji (nie tworzenia instancji) — np. wymuszenie obecności konkretnych metod
  • ORM-y (np. Django Model) — metaklasy automatycznie przekształcają zwykłe atrybuty klasy (np. pole = CharField()) w logikę mapowania na kolumny bazy danych
Metaklasy to jeden z najbardziej "magicznych" i rzadko potrzebnych mechanizmów Pythona — cytat przypisywany Timowi Petersowi: "metaklasy to głębsza magia, o której 99% użytkowników nawet nie musi się martwić" — ale są kluczowe do zrozumienia, jak biblioteki jak Django/SQLAlchemy "pod maską" budują swoje klasy.

6. Context managery (menedżery kontekstu)

Protokół stojący za instrukcją with (patrz przedmiot Języki skryptowe, operacje na plikach) — pozwala zagwarantować wykonanie kodu "sprzątającego" (np. zamknięcie pliku, zwolnienie blokady) niezależnie od tego, czy w bloku wystąpił wyjątek.

Protokół — __enter__ i __exit__

class Timer:
    def __enter__(self):
        import time
        self.start = time.time()
        return self                     # to, co trafia do zmiennej po "as"

    def __exit__(self, exc_type, exc_value, traceback):
        import time
        print(f"Czas: {time.time() - self.start:.4f}s")
        return False                    # False = nie "połykaj" wyjątku (propaguj dalej)

with Timer() as t:
    suma = sum(range(1000000))
# automatycznie wywołane __exit__ przy wyjściu z bloku

Parametry __exit__

Jeśli w bloku with wystąpił wyjątek, __exit__ otrzymuje jego typ, wartość i traceback (wszystkie None, jeśli nie wystąpił żaden wyjątek):

  • return False (lub brak return) — wyjątek jest propagowany dalej, jak zwykle
  • return True — wyjątek zostaje "wygaszony" (nie propaguje się poza blok with) — używać ostrożnie, bo łatwo ukryć prawdziwy błąd

Prostsza alternatywa — contextlib.contextmanager

from contextlib import contextmanager
import time

@contextmanager
def zmierz_czas():
    start = time.time()
    yield                          # tutaj wykonuje się kod bloku "with"
    print(f"Czas: {time.time()-start:.4f}s")

with zmierz_czas():
    suma = sum(range(1000000))

Dekorator @contextmanager zamienia funkcję generatorową w context manager — kod przed yield odpowiada __enter__, kod po yield odpowiada __exit__.

Typowe zastosowania: zarządzanie zasobami (pliki, połączenia sieciowe/bazodanowe, blokady/muteksy), tymczasowa zmiana stanu (np. tymczasowa zmiana katalogu roboczego, wyłączenie logowania na czas jakiejś operacji, a potem automatyczne przywrócenie).

7. __slots__ i dataclasses

__slots__ — ograniczenie atrybutów instancji

Domyślnie każda instancja przechowuje swoje atrybuty w słowniku (__dict__) — elastyczne (można dodawać atrybuty dynamicznie, patrz punkt 1), ale zużywa więcej pamięci. __slots__ jawnie ogranicza zestaw dozwolonych atrybutów, eliminując __dict__:

class Punkt:
    __slots__ = ('x', 'y')     # tylko te dwa atrybuty są dozwolone

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Punkt(1, 2)
# p.z = 5   # BŁĄD: AttributeError — 'z' nie jest w __slots__

Dataclasses — ograniczenie boilerplate

Dekorator @dataclass (moduł dataclasses, od Python 3.7) automatycznie generuje __init__, __repr__, __eq__ na podstawie zadeklarowanych pól — eliminuje powtarzalny kod dla klas, które głównie "przechowują dane":

from dataclasses import dataclass

@dataclass
class Punkt:
    x: int
    y: int
    etykieta: str = "punkt"    # wartość domyślna

p1 = Punkt(1, 2)
p2 = Punkt(1, 2)
print(p1)              # Punkt(x=1, y=2, etykieta='punkt') — __repr__ za darmo
print(p1 == p2)        # True — __eq__ za darmo (porównuje wartości pól)

Porównanie z "ręcznym" pisaniem klasy

# bez dataclass — trzeba napisać to wszystko ręcznie:
class PunktRecznie:
    def __init__(self, x, y, etykieta="punkt"):
        self.x, self.y, self.etykieta = x, y, etykieta
    def __repr__(self):
        return f"PunktRecznie(x={self.x}, y={self.y}, etykieta={self.etykieta!r})"
    def __eq__(self, inny):
        return (self.x, self.y, self.etykieta) == (inny.x, inny.y, inny.etykieta)

@dataclass + frozen=True — niemutowalność

@dataclass(frozen=True)
class PunktStaly:
    x: int
    y: int

p = PunktStaly(1, 2)
# p.x = 5    # BŁĄD: FrozenInstanceError — jak niemutowalne typy z punktu o mutowalności
@dataclass i __slots__ można łączyć (@dataclass(slots=True) od Python 3.10) — najlepsze z obu: mało boilerplate'u i mała pamięć na instancję.

8. Kopiowanie obiektów — copy i deepcopy

Bezpośrednie nawiązanie do mutowalności (patrz przedmiot Języki skryptowe) — dla obiektów złożonych, samo przypisanie (b = a) tylko kopiuje referencję, nie tworzy nowego obiektu.

Kopia płytka (shallow copy)

import copy

a = [[1,2], [3,4]]
b = copy.copy(a)          # albo a[:] / list(a)

b.append([5,6])            # nie wpływa na a — to nowa, osobna lista "na zewnątrz"
b[0].append(99)             # WPŁYWA na a[0]! — zagnieżdżone listy są WSPÓLNE
print(a)   # [[1, 2, 99], [3, 4]]

Kopia płytka tworzy nowy obiekt "zewnętrzny", ale elementy wewnątrz (jeśli same są mutowalne, np. zagnieżdżone listy) są współdzielone (te same referencje) między oryginałem i kopią.

Kopia głęboka (deep copy)

c = copy.deepcopy(a)
c[0].append(100)
print(a)   # bez zmian — c jest CAŁKOWICIE niezależne, rekurencyjnie skopiowane

deepcopy rekurencyjnie kopiuje wszystkie zagnieżdżone obiekty mutowalne — wynikowy obiekt jest w pełni niezależny od oryginału, na każdym poziomie zagnieżdżenia.

Porównanie

Przypisanie (b=a)Kopia płytkaKopia głęboka

Dostosowanie kopiowania własnych klas

class Kontener:
    def __init__(self, dane):
        self.dane = dane

    def __copy__(self):              # własna logika dla copy.copy()
        return Kontener(self.dane)

    def __deepcopy__(self, memo):    # własna logika dla copy.deepcopy()
        return Kontener(copy.deepcopy(self.dane, memo))

Parametr memo (słownik) chroni przed nieskończoną rekurencją przy strukturach cyklicznych (obiekt zawierający referencję do samego siebie) — deepcopy pamięta, co już skopiował.

Typowe pytanie: dla podanej struktury zagnieżdżonych list/obiektów, przewidź wynik modyfikacji po copy.copy() vs copy.deepcopy() — klasyczny sposób sprawdzenia zrozumienia różnicy między referencją a rzeczywistą, pełną kopią danych.
