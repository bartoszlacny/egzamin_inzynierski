Języki skryptowe (Python)

1. Typy mutowalne i niemutowalne

Mutowalność — czy obiekt można zmienić "w miejscu" (bez tworzenia nowego obiektu) po jego utworzeniu.

Niemutowalne (immutable)Mutowalne (mutable)
int, float, boollist
strdict
tupleset
frozensetobiekty klas użytkownika (domyślnie)

Przykład — string (niemutowalny)

s = "abc"
s[0] = "x"       # BŁĄD: TypeError — stringi są niemutowalne!
s = s + "d"      # OK, ale to tworzy CAŁKIEM NOWY obiekt string, nie modyfikuje starego

Przykład — lista (mutowalna)

lista = [1, 2, 3]
lista[0] = 99        # OK — modyfikacja w miejscu, ten sam obiekt
lista.append(4)      # OK — też modyfikacja w miejscu

Konsekwencja — zmienne jako referencje

a = [1, 2, 3]
b = a            # b i a wskazują na TEN SAM obiekt listy
b.append(4)
print(a)         # [1, 2, 3, 4] — zmiana przez b widoczna też w a!

x = 5
y = x            # y kopiuje wartość (int jest niemutowalny)
y = y + 1
print(x)         # 5 — x się nie zmieniło
Klasyczna pułapka: domyślny argument mutowalny w funkcji (def f(lista=[]):) jest tworzony tylko raz, przy definicji funkcji — kolejne wywołania współdzielą ten sam obiekt listy, co prowadzi do nieoczekiwanego "zapamiętywania" danych między wywołaniami!

Krotka (tuple) vs lista

Krotka jest niemutowalna, ale jeśli zawiera mutowalny obiekt (np. listę), ten obiekt wewnątrz można wciąż modyfikować — niemutowalność krotki dotyczy tylko samych referencji do elementów, nie ich zawartości:

t = ([1,2], 3)
t[0].append(99)   # OK! modyfikujemy listę WEWNĄTRZ krotki
# t[1] = 5        # BŁĄD — nie można zmienić samej referencji w krotce

2. Podstawowe struktury danych

StrukturaCechaPrzykład

Lista — podstawowe operacje

l = [1, 2, 3]
l.append(4)          # dodanie na koniec
l.insert(0, 0)        # wstawienie na konkretną pozycję
l.remove(2)          # usunięcie pierwszego wystąpienia wartości 2
l.pop()              # usunięcie i zwrócenie ostatniego elementu
l[1:3]               # wycinek (slicing) — elementy od indeksu 1 do 2
l.sort()             # sortowanie w miejscu
sorted(l)            # sortowanie — zwraca NOWĄ listę, oryginał bez zmian

Słownik — podstawowe operacje

d = {"imie": "Jan", "wiek": 25}
d["email"] = "jan@example.com"   # dodanie/nadpisanie klucza
d.get("wiek", 0)                  # bezpieczny odczyt z wartością domyślną
d.keys(), d.values(), d.items()   # widoki kluczy / wartości / par (klucz,wartość)
del d["wiek"]                     # usunięcie klucza
"imie" in d                       # sprawdzenie, czy klucz istnieje

Zbiór — operacje mnogościowe

a = {1, 2, 3}
b = {2, 3, 4}
a | b   # unia: {1,2,3,4}
a & b   # przecięcie: {2,3}
a - b   # różnica: {1}
a ^ b   # różnica symetryczna: {1,4}

Kiedy który wybrać?

  • lista — gdy kolejność ma znaczenie i elementy mogą się powtarzać
  • krotka — jak lista, ale dane, które nie powinny się zmieniać (np. współrzędne punktu)
  • zbiór — gdy interesują nas tylko unikalne elementy, kolejność nieistotna, szybkie sprawdzanie przynależności (\(O(1)\) średnio, jak w tablicy haszującej)
  • słownik — gdy potrzebne mapowanie klucz→wartość, szybki dostęp po kluczu (\(O(1)\) średnio)

3. Funkcje i zasięg zmiennych

Definicja funkcji

def suma(a, b=0):          # b ma wartość domyślną
    return a + b

suma(3, 4)      # 7
suma(3)         # 3 (b domyślnie 0)
suma(b=5, a=2)  # 7 (argumenty nazwane, kolejność nieistotna)

*args i **kwargs

def f(*args, **kwargs):
    print(args)     # tuple pozycyjnych argumentów
    print(kwargs)   # dict argumentów nazwanych

f(1, 2, 3, x=4, y=5)
# args = (1, 2, 3)
# kwargs = {'x': 4, 'y': 5}

Zasięg zmiennych — reguła LEGB

Kolejność, w jakiej Python szuka zmiennej: Local (lokalny, wewnątrz funkcji) → Enclosing (funkcja zewnętrzna, przy zagnieżdżonych funkcjach) → Global (poziom modułu) → Built-in (wbudowane, np. len, print).

x = "globalna"

def zewnetrzna():
    x = "enclosing"
    def wewnetrzna():
        x = "lokalna"
        print(x)      # "lokalna" (znaleziona najpierw, poziom L)
    wewnetrzna()

zewnetrzna()

Słowa kluczowe global i nonlocal

licznik = 0

def zwieksz():
    global licznik    # bez tego, przypisanie stworzyłoby NOWĄ zmienną lokalną
    licznik += 1

def zewnetrzna():
    x = 0
    def wewnetrzna():
        nonlocal x     # odnosi się do x z funkcji otaczającej (enclosing), nie globalnej
        x += 1
    wewnetrzna()
    print(x)   # 1
Klasyczna pułapka: samo odczytanie zmiennej z zewnętrznego zasięgu działa bez żadnych słów kluczowych — global/nonlocal są potrzebne tylko, gdy chcemy przypisać (zmienić) wartość tej zmiennej z wnętrza funkcji.

Funkcje jako obiekty pierwszej klasy

Funkcje można przekazywać jako argumenty, zwracać z innych funkcji, przypisywać do zmiennych — podstawa dla dekoratorów i programowania funkcyjnego w Pythonie:

def kwadrat(x): return x*x
operacja = kwadrat        # przypisanie funkcji do zmiennej
print(operacja(5))        # 25

def zastosuj(f, x): return f(x)
zastosuj(kwadrat, 5)      # 25 — funkcja jako argument

4. Operacje na plikach i systemie plików

Otwieranie plików

plik = open("dane.txt", "r", encoding="utf-8")
tresc = plik.read()
plik.close()

Menedżer kontekstu with (zalecane!)

with open("dane.txt", "r", encoding="utf-8") as plik:
    tresc = plik.read()
# plik automatycznie zamknięty po wyjściu z bloku, nawet jeśli wystąpi wyjątek

plik.write("tekst\n")
plik.writelines(["linia1\n", "linia2\n"])

Moduł os i os.path — operacje na systemie plików

import os

os.listdir(".")             # lista plików/katalogów w bieżącym katalogu
os.path.exists("plik.txt")  # czy plik/katalog istnieje
os.path.join("folder", "plik.txt")  # łączenie ścieżek (przenośne między systemami)
os.makedirs("nowy_folder")  # tworzenie katalogu (z podkatalogami)
os.remove("plik.txt")       # usunięcie pliku
os.rename("stary.txt", "nowy.txt")

Moduł pathlib (nowocześniejsze podejście, obiektowe)

from pathlib import Path

with jest zdecydowanie preferowane nad ręcznym open()/close() — gwarantuje zamknięcie pliku nawet przy wyjątku, eliminując klasyczny błąd "zapomnianego" close() (analogiczny do wycieków pamięci w C, patrz przedmioty o C).

5. Listy składane (list comprehensions) i generatory

Listy składane — składnia

kwadraty = [x**2 for x in range(10)]
# odpowiednik:
kwadraty = []
for x in range(10):
    kwadraty.append(x**2)

Z warunkiem (filtrowanie)

parzyste = [x for x in range(20) if x % 2 == 0]

Z if-else (wybór wartości, nie filtrowanie!)

etykiety = ["parzysta" if x % 2 == 0 else "nieparzysta" for x in range(5)]

Zagnieżdżone (np. spłaszczanie listy list)

macierz = [[1,2,3], [4,5,6]]
splaszczona = [x for wiersz in macierz for x in wiersz]
# [1, 2, 3, 4, 5, 6]

Analogiczne konstrukcje — dict i set comprehension

kwadraty_dict = {x: x**2 for x in range(5)}     # {0:0, 1:1, 2:4, 3:9, 4:16}
unikalne_dlugosci = {len(s) for s in ["a","bb","ccc","dd"]}  # {1, 2, 3}

Generatory — wyrażenie generatorowe

gen = (x**2 for x in range(10))   # nawiasy okrągłe, nie kwadratowe!
next(gen)   # 0
next(gen)   # 1

W odróżnieniu od listy składanej, generator nie tworzy całej struktury w pamięci naraz — elementy są liczone "na żądanie" (lazy evaluation), jeden po drugim, w miarę iteracji.

Funkcje generatorowe (yield)

def liczby_do(n):
    for i in range(n):
        yield i

for x in liczby_do(5):
    print(x)   # 0 1 2 3 4

yield "zamraża" stan funkcji między kolejnymi wywołaniami next() — funkcja pamięta, gdzie skończyła, i wraca do tego miejsca przy następnym żądaniu wartości.

Lista składana vs generator — kiedy który?

Lista składanaGenerator
Pamięćcała struktura naraz w pamięcitylko jeden element na raz (leniwie)
Wielokrotne przejścietak, można iterować wiele razynie — po wyczerpaniu trzeba stworzyć nowy generator
Zastosowaniegdy potrzebujesz pełnej listy (np. do sort(), indeksowania)duże/nieskończone sekwencje, przetwarzanie strumieniowe, oszczędność pamięci
Typowe pytanie: dlaczego przy przetwarzaniu bardzo dużego pliku (miliony linii) lepiej użyć generatora niż listy składanej — bo generator przetwarza linię po linii, nie wczytując całości do pamięci naraz.

6. Obsługa wyjątków

Podstawowa składnia

try:
    wynik = 10 / 0
except ZeroDivisionError:
    print("Nie można dzielić przez zero!")
except (TypeError, ValueError) as e:
    print(f"Błąd typu lub wartości: {e}")
except Exception as e:
    print(f"Inny błąd: {e}")   # wyłapuje wszystkie pozostałe wyjątki
else:
    print("Kod wykonany, jeśli NIE wystąpił wyjątek")
finally:
    print("Wykonuje się ZAWSZE — niezależnie od wyjątku")

Kolejność bloków

  • try — kod, który może zgłosić wyjątek
  • except — obsługa konkretnego typu (lub typów) wyjątku; można mieć wiele bloków, sprawdzanych po kolei od najbardziej specyficznego
  • else (opcjonalny) — wykonuje się, tylko gdy try zakończył się bez wyjątku
  • finally (opcjonalny) — wykonuje się zawsze, nawet jeśli w except był return/kolejny wyjątek — typowe miejsce na zwalnianie zasobów (choć with zwykle robi to lepiej dla plików, patrz punkt 4)

Zgłaszanie własnych wyjątków — raise

def sprawdz_wiek(wiek):
    if wiek < 0:
        raise ValueError("Wiek nie może być ujemny")
    return wiek

try:
    sprawdz_wiek(-5)
except ValueError as e:
    print(e)   # "Wiek nie może być ujemny"

Własne klasy wyjątków

class MojWyjatek(Exception):
    pass

class BladWalidacji(MojWyjatek):
    def __init__(self, pole, wiadomosc):
        self.pole = pole
        super().__init__(wiadomosc)

raise BladWalidacji("email", "Nieprawidlowy format email")

Własne wyjątki dziedziczą (bezpośrednio lub pośrednio) po Exception — pozwala to budować hierarchię wyjątków specyficzną dla danej aplikacji, wyłapywaną selektywnie.

Popularne wbudowane wyjątki

WyjątekSytuacja

Dobra praktyka: łap konkretne typy wyjątków (except ValueError), nie "goły" except: (bez typu) — inaczej łatwo przypadkiem "połknąć" też błędy programistyczne (np. literówkę w nazwie zmiennej), które powinny przerwać program i zostać zauważone.

7. Dekoratory

Funkcja, która przyjmuje inną funkcję jako argument i zwraca nową funkcję, "opakowując" (wrapping) jej zachowanie — pozwala dodać wspólną logikę (logowanie, pomiar czasu, sprawdzanie uprawnień) bez modyfikowania kodu oryginalnej funkcji.

Dekorator "od podstaw" (bez składni @)

def moj_dekorator(funkcja):
    def wrapper(*args, **kwargs):
        print("Przed wywołaniem")
        wynik = funkcja(*args, **kwargs)
        print("Po wywołaniu")
        return wynik
    return wrapper

def powiedz_czesc():
    print("Cześć!")

powiedz_czesc = moj_dekorator(powiedz_czesc)   # "ręczne" udekorowanie
powiedz_czesc()
# Przed wywołaniem
# Cześć!
# Po wywołaniu

Składnia @ — "cukier syntaktyczny"

@moj_dekorator
def powiedz_czesc():
    print("Cześć!")

powiedz_czesc()   # to samo co wyżej — @dekorator to skrót od: f = dekorator(f)

Przykład praktyczny — pomiar czasu wykonania

import time

def zmierz_czas(funkcja):
    def wrapper(*args, **kwargs):
        start = time.time()
        wynik = funkcja(*args, **kwargs)
        print(f"Czas wykonania: {time.time()-start:.4f}s")
        return wynik
    return wrapper

@zmierz_czas
def dlugie_obliczenia():
    time.sleep(1)

dlugie_obliczenia()   # wypisze czas wykonania ~1s

Dekorator z własnymi parametrami

def powtorz(n):                      # funkcja zwracająca dekorator
    def dekorator(funkcja):
        def wrapper(*args, **kwargs):
            for _ in range(n):
                funkcja(*args, **kwargs)
        return wrapper
    return dekorator

@powtorz(3)
def przywitaj():
    print("Witaj!")

przywitaj()   # wypisze "Witaj!" trzy razy
