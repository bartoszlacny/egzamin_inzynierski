Programowanie proceduralne (C)

Ten przedmiot rozwija tematy ze "Podstaw programowania" — jeśli coś jest niejasne, warto zerknąć też tam.

1. Wskaźniki podwójne i tablice wskaźników

Wskaźnik na wskaźnik (podwójny)

int x = 10;
int *p = &x;      // p przechowuje adres x
int **pp = &p;    // pp przechowuje adres p (czyli "adres adresu x")

printf("%d", **pp);  // dereferencja dwukrotna → 10
*p = 20;             // zmienia x na 20
**pp = 30;           // też zmienia x, tym razem przez podwójną dereferencję

Zastosowanie — modyfikacja wskaźnika przez funkcję

Zwykły wskaźnik jako parametr pozwala zmienić wartość, na którą wskazuje, ale nie sam wskaźnik (bo przekazywany jest przez wartość — kopia adresu). Żeby funkcja mogła zmienić sam wskaźnik (np. przydzielić mu nową pamięć), potrzeba wskaźnika na wskaźnik:

void alokuj(int **wp, int rozmiar) {
    *wp = malloc(rozmiar * sizeof(int));  // zmienia wskaźnik w main()
}

int main() {
    int *tab = NULL;
    alokuj(&tab, 10);   // przekazujemy adres wskaźnika
    tab[0] = 5;          // tab wskazuje już na przydzieloną pamięć
    free(tab);
}

Tablica wskaźników

Tablica, której każdy element jest wskaźnikiem (a nie zwykłą wartością):

int a=1, b=2, c=3;
int *tab[3] = {&a, &b, &c};   // tablica 3 wskaźników na int

printf("%d", *tab[1]);   // 2 (dereferencja drugiego elementu)

Tablica stringów jako tablica wskaźników

char *dni[] = {"Poniedzialek", "Wtorek", "Sroda"};
printf("%s", dni[1]);   // "Wtorek"

Każdy element dni[i] to wskaźnik char* na osobny napis w pamięci — w odróżnieniu od dwuwymiarowej tablicy char dni[3][20], gdzie wszystkie napisy mają tę samą, ustaloną z góry długość wiersza.

Wskaźnik na tablicę wskaźników

int **ptab = tab;    // ptab wskazuje na pierwszy element tablicy wskaźników
printf("%d", *ptab[0]);   // dereferencja przez ptab
Klasyczne zastosowanie podwójnych wskaźników: parametry main(int argc, char **argv) — argv to tablica wskaźników na stringi (argumenty wywołania programu), stąd typ char**.

2. Dynamiczna alokacja pamięci. Wycieki pamięci

Funkcje z <stdlib.h>

int *p = malloc(n * sizeof(int));    // n elementów, niezainicjalizowane
int *q = calloc(n, sizeof(int));     // n elementów, wyzerowane
p = realloc(p, 2*n * sizeof(int));   // zmiana rozmiaru (zachowuje dane)
free(p);                             // zwolnienie pamięci

Wyciek pamięci (memory leak)

Sytuacja, gdy pamięć przydzielona dynamicznie (malloc/calloc) nie zostaje nigdy zwolniona (free), mimo że program już do niej nie ma dostępu (utracił jedyny wskaźnik na ten blok). Pamięć pozostaje zajęta aż do zakończenia całego programu.

Typowe przyczyny wycieków

int *p = malloc(100);
p = malloc(200);   // BŁĄD: nadpisano wskaźnik, stary blok 100 bajtów "zgubiony" (wyciek)
// ...
free(p);           // zwalnia tylko drugi blok (200 bajtów)
  • utrata jedynego wskaźnika do bloku (nadpisanie, wyjście ze scope zmiennej bez wcześniejszego free)
  • wcześniejszy return/break/wyjątek pomijający free() w dalszej części funkcji
  • alokacja w pętli bez zwalniania poprzednich iteracji

Inne błędy związane z pamięcią dynamiczną

  • dangling pointer — użycie wskaźnika po free() (pamięć mogła już zostać przydzielona czemuś innemu)
  • double free — dwukrotne wywołanie free() na tym samym wskaźniku — niezdefiniowane zachowanie, często crash
  • buffer overflow — zapis poza przydzielonym blokiem pamięci
Dobra praktyka: po free(p) zawsze ustaw p = NULL; — próba dereferencji NULL daje natychmiastowy, łatwy do zdiagnozowania błąd, zamiast subtelnego błędu "dangling pointer".

Narzędzia do wykrywania wycieków

W praktyce programiści używają narzędzi jak valgrind (Linux) do automatycznego wykrywania wycieków pamięci i błędnych dostępów podczas testowania programu.

3. Łańcuchy znakowe w C

String w C to zwykła tablica char, zakończona bajtem NUL ('\0', wartość 0) — nie ma osobnego typu string jak w innych językach.

char napis[] = "Ala";     // {'A','l','a','\0'} — 4 bajty, nie 3!
char *wsk = "Ala";        // wskaźnik na literał (nie modyfikować!)

Funkcje z <string.h>

FunkcjaDziałanie
strlen(s)długość napisu (bez liczenia '\0')
strcpy(dest, src)kopiowanie napisu
strncpy(dest, src, n)kopiowanie max n znaków (bezpieczniejsze)
strcat(dest, src)doklejenie napisu na koniec
strcmp(s1, s2)porównanie leksykograficzne (0 = równe)
strchr(s, c)szukanie znaku w napisie
strstr(s1, s2)szukanie podnapisu
sprintf(bufor, format, ...)formatowanie danych do napisu
atoi(s), atof(s)konwersja napisu na int/float
Klasyczna pułapka: strcpy/strcat nie sprawdzają, czy docelowy bufor jest wystarczająco duży — łatwo o przepełnienie bufora (buffer overflow). Bezpieczniejsze są warianty z limitem długości (strncpy, strncat) — ale i tak trzeba pilnować, żeby wynik zawsze kończył się '\0'.

Iteracja po znakach napisu

char *s = "Ala";
for (int i = 0; s[i] != '\0'; i++) {
    putchar(s[i]);
}
// albo równoważnie przez wskaźnik:
for (char *p = s; *p != '\0'; p++) {
    putchar(*p);
}

Tablica dwuwymiarowa znaków vs tablica wskaźników na stringi

char a[3][10] = {"Ala", "Ola", "Ela"};  // każdy wiersz to 10 bajtów, stały rozmiar
char *b[3] = {"Ala", "Ola", "Ela"};     // 3 wskaźniki na napisy o dowolnej długości

4. Struktury w C

Definicja i dostęp

struct Osoba {
    char imie[30];
    int wiek;
};

struct Osoba o1 = {"Jan", 25};
o1.wiek = 26;                   // dostęp przez kropkę

struct Osoba *wo = &o1;
wo->wiek = 27;                  // dostęp przez wskaźnik (skrót od (*wo).wiek)

Struktury zagnieżdżone

struct Adres { char miasto[30]; };
struct Osoba {
    char imie[30];
    struct Adres adres;
};

struct Osoba o;
strcpy(o.adres.miasto, "Warszawa");

Struktury i dynamiczna alokacja

struct Osoba *p = malloc(sizeof(struct Osoba));
strcpy(p->imie, "Anna");
p->wiek = 30;
free(p);

Tablice struktur

struct Osoba grupa[5];
grupa[0].wiek = 20;

Struktury jako parametry funkcji

Domyślnie przekazywane przez wartość (kopiowana cała struktura — kosztowne dla dużych struktur!). Żeby modyfikować oryginał lub uniknąć kopiowania, przekazuje się wskaźnik:

void ustawWiek(struct Osoba *o, int w) {
    o->wiek = w;   // modyfikuje oryginał
}

typedef

typedef struct {
    int x, y;
} Punkt;

Punkt p = {1, 2};   // bez konieczności pisania "struct Punkt"

5. Obsługa plików w C

Otwieranie i tryby

FILE *f = fopen("dane.txt", "r");
if (f == NULL) { /* obsługa błędu */ }
...
fclose(f);
TrybZnaczenie
"r"odczyt (plik musi istnieć)
"w"zapis (nadpisuje istniejący plik lub tworzy nowy)
"a"dopisywanie na końcu pliku
"r+"/"w+"/"a+"odczyt i zapis jednocześnie
+ b (np. "rb")tryb binarny (bez konwersji końca linii)

Pliki tekstowe

fprintf(f, "%d %s\n", liczba, napis);   // zapis sformatowany
fscanf(f, "%d", &liczba);               // odczyt sformatowany
fputs("linia\n", f);
fgets(bufor, rozmiar, f);               // odczyt linii (z '\n' na końcu)

Pliki binarne

struct Osoba o = {"Jan", 25};
fwrite(&o, sizeof(struct Osoba), 1, f);    // zapis surowych bajtów struktury
fread(&o, sizeof(struct Osoba), 1, f);     // odczyt z powrotem

Pliki binarne zapisują dane dokładnie tak, jak są w pamięci (bez konwersji na tekst) — szybsze i bardziej zwarte niż tekstowe, ale nieczytelne "gołym okiem" i mniej przenośne między różnymi architekturami.

Dostęp sekwencyjny vs swobodny (random access)

  • sekwencyjny — czytanie/pisanie od początku do końca, po kolei (domyślny sposób pracy z plikiem)
  • swobodny — przeskakiwanie do dowolnego miejsca w pliku za pomocą fseek:
fseek(f, 0, SEEK_END);      // przesuń wskaźnik na koniec pliku
long rozmiar = ftell(f);    // pobierz aktualną pozycję (czyli rozmiar pliku)
fseek(f, 0, SEEK_SET);      // wróć na początek
fseek(f, 10, SEEK_CUR);     // przesuń się 10 bajtów od aktualnej pozycji
rewind(f);                  // skrót: wróć na sam początek

Argumenty SEEK_SET (od początku), SEEK_CUR (od aktualnej pozycji), SEEK_END (od końca) określają punkt odniesienia przesunięcia.

Dostęp swobodny ma sens głównie dla plików binarnych o rekordach stałego rozmiaru (można łatwo obliczyć offset n-tego rekordu jako n * sizeof(rekord)) — dla plików tekstowych o zmiennej długości linii jest to znacznie trudniejsze w praktyce.

Sprawdzanie końca pliku i błędów

feof(f) — czy osiągnięto koniec pliku; ferror(f) — czy wystąpił błąd odczytu/zapisu.

6. Wskaźniki do funkcji

int dodaj(int a, int b) { return a+b; }
int odejmij(int a, int b) { return a-b; }

int (*op)(int, int) = dodaj;   // wskaźnik na funkcję int f(int,int)
printf("%d", op(2,3));         // 5

op = odejmij;
printf("%d", op(5,3));         // 2

Funkcja jako parametr

int wykonaj(int (*f)(int,int), int a, int b) {
    return f(a,b);
}
wykonaj(dodaj, 3, 4);   // 7

Tablica wskaźników do funkcji (dyspozytor)

int (*operacje[2])(int,int) = {dodaj, odejmij};
int wybor = 0;
printf("%d", operacje[wybor](2,3));  // 5

Typowe zastosowania

  • przekazanie funkcji porównującej do qsort(): 
    int porownaj(const void *a, const void *b) {
    return *(int*)a - *(int*)b;
}
qsort(tab, n, sizeof(int), porownaj);
  • implementacja callbacków (funkcja wywoływana "z zewnątrz" w odpowiedzi na zdarzenie)
  • tablice funkcji jako alternatywa dla długich switch (dyspozytor operacji na podstawie indeksu)

7. Klasy zmiennych — czas trwania, zasięg, łączność

Czas trwania (storage duration)

  • automatyczny — zmienne lokalne (domyślnie); tworzone przy wejściu do bloku, niszczone przy wyjściu (żyją na stosie)
  • statyczny — zmienne static i globalne; istnieją przez cały czas działania programu
  • dynamiczny — pamięć z malloc/calloc; żyje, aż do jawnego free()

Zasięg (scope)

  • blokowy — zmienna widoczna tylko wewnątrz bloku { }, w którym została zadeklarowana
  • funkcyjny — widoczna w całej funkcji (zwykłe zmienne lokalne)
  • plikowy (globalny) — zmienna zadeklarowana poza funkcjami, widoczna w całym pliku (i innych plikach, jeśli nie jest static)

Łączność (linkage)

  • brak łączności — zmienne lokalne, każda funkcja/blok ma "swoją" niezależną kopię
  • łączność wewnętrzna (internal) — zmienna/funkcja static na poziomie pliku — widoczna tylko w tym jednym pliku .c, ukryta przed innymi plikami
  • łączność zewnętrzna (external) — zwykła zmienna/funkcja globalna (bez static) — widoczna też w innych plikach przez deklarację extern

Słowa kluczowe klas pamięci

SłowoZnaczenie
auto domyślna klasa zmiennych lokalnych (rzadko pisana jawnie — to i tak wartość domyślna)
static (lokalnie w funkcji) zmienna zachowuje wartość między wywołaniami funkcji, ale widoczna tylko w niej
static (globalnie w pliku) zmienna/funkcja widoczna tylko w tym pliku .c (łączność wewnętrzna)
extern deklaruje, że zmienna/funkcja jest zdefiniowana w innym pliku — pozwala z niej korzystać bez ponownej definicji
register sugestia dla kompilatora, żeby trzymać zmienną w rejestrze procesora (szybszy dostęp) — dziś w praktyce ignorowana, bo kompilatory same optymalizują to lepiej

Przykład — static vs zwykła zmienna lokalna

void f() {
    int a = 0;          // zwykła: za każdym wywołaniem tworzona od nowa
    static int b = 0;   // static: pamięta wartość między wywołaniami

    a++; b++;
    printf("a=%d b=%d\n", a, b);
}
// f(); f(); f();  →  wypisze: a=1 b=1 / a=1 b=2 / a=1 b=3

Przykład — extern między plikami

// plik1.c
int licznik = 0;   // definicja (łączność zewnętrzna, bo bez static)

// plik2.c
extern int licznik;   // deklaracja: "ta zmienna istnieje gdzieś indziej"
void f() { licznik++; }
Typowe pytanie egzaminacyjne: prześledź, jaka wartość zostanie wypisana po kilku wywołaniach funkcji ze zmienną static — trzeba pamiętać, że inicjalizacja (=0) wykonuje się tylko raz, przy pierwszym wywołaniu.

8. Kompilacja wieloplikowa

Duże programy dzieli się na wiele plików .c (moduły) — łatwiej zarządzać kodem, można kompilować tylko zmieniony plik, a nie całość od nowa.

Deklaracja vs definicja

  • deklaracja — zapowiada istnienie funkcji/zmiennej (jej typ i sygnaturę), bez rezerwowania pamięci: int suma(int a, int b);
  • definicja — pełna implementacja (dla funkcji) lub rezerwacja pamięci (dla zmiennej): int suma(int a, int b) { return a+b; }

Pliki nagłówkowe (.h)

Zawierają deklaracje (prototypy funkcji, definicje struktur, stałe) współdzielone między wieloma plikami .c:

// matematyka.h
#ifndef MATEMATYKA_H
#define MATEMATYKA_H

int suma(int a, int b);
int roznica(int a, int b);

#endif
// matematyka.c
#include "matematyka.h"

int suma(int a, int b) { return a+b; }
int roznica(int a, int b) { return a-b; }
// main.c
#include <stdio.h>
#include "matematyka.h"

int main() {
    printf("%d", suma(2,3));
    return 0;
}

Proces budowania programu

  1. preprocessing — rozwinięcie #include, #define itd. (patrz Podstawy programowania, dyrektywy preprocesora)
  2. kompilacja — każdy plik .c zamieniany osobno na plik obiektowy (.o/.obj) — zawiera skompilowany kod maszynowy, ale jeszcze bez rozwiązanych odwołań do symboli z innych plików
  3. linkowanie (łączenie) — linker łączy wszystkie pliki obiektowe w jeden plik wykonywalny, rozwiązując odwołania między nimi (np. wywołanie suma() z main.c łączone jest z jego definicją w matematyka.c)
gcc -c matematyka.c -o matematyka.o    # tylko kompilacja
gcc -c main.c -o main.o                # tylko kompilacja
gcc matematyka.o main.o -o program     # linkowanie w plik wykonywalny
Strażnik nagłówka (#ifndef/#define/#endif) jest konieczny, bo ten sam plik .h może zostać dołączony pośrednio wielokrotnie (np. przez różne inne nagłówki) — bez strażnika powstałby błąd redefinicji.

Błędy linkera vs kompilatora

  • błąd kompilacji — problem składniowy/typów w pojedynczym pliku (np. brak średnika, zły typ)
  • błąd linkowania — np. "undefined reference to `suma`" — funkcja zadeklarowana (w .h), ale nigdzie niezdefiniowana lub plik z definicją nie został dołączony do linkowania

9. Obsługa błędów w C

C nie ma wyjątków (jak np. C++/Java) — błędy sygnalizuje się przez wartości zwracane, zmienną globalną errno i kody wyjścia programu.

Kod wyjścia programu

int main() {
    if (/* coś poszło źle */) {
        return 1;    // niezerowy kod = błąd (konwencja)
    }
    return 0;        // 0 = sukces
}

Funkcja exit(kod) z <stdlib.h> pozwala zakończyć program z dowolnego miejsca (nie tylko z main), z tym samym znaczeniem kodu.

errno

Globalna zmienna (z <errno.h>) ustawiana przez wiele funkcji bibliotecznych po napotkaniu błędu — zawiera kod konkretnego błędu:

#include <errno.h>
#include <string.h>

FILE *f = fopen("brak_pliku.txt", "r");
if (f == NULL) {
    printf("Blad: %s\n", strerror(errno));   // czytelny opis błędu
    // albo:
    perror("Nie udalo sie otworzyc pliku");  // wypisuje własny komunikat + opis errno
}
errno nie jest automatycznie zerowane przez funkcje, które się powiodły — sprawdzaj je tylko zaraz po wywołaniu funkcji, która zgłosiła błąd (np. zwróciła NULL lub -1), nie w oderwaniu od kontekstu.

Konwencje sygnalizowania błędów przez wartość zwracaną

WzorzecPrzykład
specjalna wartość jako błądfopen() zwraca NULL, read() zwraca -1
kod błędu jako wynik funkcji0 = sukces, wartość różna od 0 = konkretny kod błędu
parametr wyjściowy + status jako returnint wczytaj(int *wynik) — return mówi czy się udało, a wynik trafia przez wskaźnik

Asercje

assert(warunek) z <assert.h> — przerywa program (i wypisuje komunikat), jeśli warunek jest fałszywy; przydatne do wychwytywania błędów logicznych/programistycznych podczas debugowania (nie do obsługi normalnych błędów wejścia użytkownika, bo w wersji "release" asercje bywają wyłączane).

10. Funkcje o zmiennej liczbie argumentów

Mechanizm z <stdarg.h> pozwalający napisać funkcję przyjmującą dowolną liczbę argumentów — tak jak działa np. wbudowane printf(format, ...).

Makra stdarg.h

MakroDziałanie
va_listtyp przechowujący "stan" listy argumentów
va_start(lista, ostatni_staly)inicjalizuje listę, zaczynając zaraz po ostatnim znanym (nazwanym) parametrze
va_arg(lista, typ)pobiera kolejny argument o podanym typie i przesuwa się dalej
va_end(lista)"sprząta" po użyciu listy — obowiązkowe na końcu

Przykład — własna funkcja sumująca dowolną liczbę liczb

#include <stdarg.h>

int suma(int liczbaArgumentow, ...) {
    va_list lista;
    va_start(lista, liczbaArgumentow);

    int wynik = 0;
    for (int i = 0; i < liczbaArgumentow; i++) {
        wynik += va_arg(lista, int);
    }

    va_end(lista);
    return wynik;
}

int main() {
    printf("%d", suma(3, 10, 20, 30));   // 60
    printf("%d", suma(2, 5, 7));         // 12
}
Funkcja musi jakoś wiedzieć, ile argumentów odebrać i jakiego są typu — sam mechanizm va_arg tego nie sprawdza (brak informacji o typach w czasie działania). Dlatego zwykle przekazuje się dodatkowy parametr z liczbą argumentów (jak wyżej) albo — jak w printf — parsuje się z tekstu formatującego (%d, %s itd.), żeby wiedzieć, ile i jakiego typu argumentów oczekiwać.

Typowe zastosowanie — funkcje logujące/formatujące

void logInfo(const char *format, ...) {
    va_list args;
    va_start(args, format);
    vprintf(format, args);   // przekazanie listy dalej do vprintf
    va_end(args);
}
