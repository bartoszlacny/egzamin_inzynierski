Algorytmy i struktury danych

1. Złożoność obliczeniowa i notacja asymptotyczna

Złożoność czasowa i pamięciowa

  • czasowa — jak liczba operacji rośnie wraz z rozmiarem danych \(n\)
  • pamięciowa — ile dodatkowej pamięci (poza samymi danymi wejściowymi) zużywa algorytm

Notacje asymptotyczne

  • \(O(f(n))\) — górne ograniczenie (algorytm działa "nie gorzej niż" \(f(n)\))
  • \(\Omega(f(n))\) — dolne ograniczenie ("nie lepiej niż")
  • \(\Theta(f(n))\) — ograniczenie dokładne (i górne, i dolne jednocześnie) — najbardziej precyzyjne określenie złożoności
W praktyce ludzie często mówią "\(O(n^2)\)" mając na myśli \(\Theta(n^2)\) — formalnie \(O\) to tylko górne ograniczenie (np. \(n = O(n^2)\) też jest prawdą), ale \(\Theta\) precyzyjnie opisuje rząd wzrostu.

Klasy złożoności (od najlepszej do najgorszej)

$$O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$$

Przypadki złożoności

  • pesymistyczny (worst case) — najgorszy możliwy przypadek danych wejściowych
  • optymistyczny (best case) — najlepszy możliwy przypadek
  • średni (average case) — uśredniony po wszystkich możliwych danych wejściowych

Porównywanie efektywności

Dla dużych \(n\) liczy się rząd wzrostu, nie stałe współczynniki — algorytm \(O(n\log n)\) jest asymptotycznie lepszy od \(O(n^2)\), nawet jeśli dla małych \(n\) ten drugi bywa szybszy w praktyce (mniejsze "stałe ukryte" w notacji O).

2. Algorytmy rekurencyjne

Funkcja wywołująca samą siebie. Wymaga: warunku zakończenia (przypadek bazowy) i przypadku rekurencyjnego (zbliżającego do bazy). Każde wywołanie zajmuje ramkę na stosie wywołań — zbyt głęboka rekurencja bez warunku stopu → przepełnienie stosu (stack overflow).

Silnia

int silnia(int n) {
    if (n <= 1) return 1;
    return n * silnia(n - 1);
}

Ciąg Fibonacciego

int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
Naiwna rekurencja Fibonacciego ma złożoność \(O(2^n)\) (drzewo wywołań rośnie wykładniczo, bo te same podproblemy liczone są wielokrotnie) — poprawia się to memoizacją/programowaniem dynamicznym do \(O(n)\).

Algorytm Euklidesa (NWD)

int nwd(int a, int b) {
    if (b == 0) return a;
    return nwd(b, a % b);
}

Złożoność: \(O(\log(\min(a,b)))\)

Przeszukiwanie drzewa (rekurencyjne, in-order)

void inorder(Wezel *w) {
    if (w == NULL) return;
    inorder(w->lewy);
    printf("%d ", w->wartosc);
    inorder(w->prawy);
}

Sortowanie przez scalanie (merge sort)

Klasyczny przykład podejścia dziel i zwyciężaj: dziel tablicę na pół, sortuj rekurencyjnie każdą połowę, scal posortowane połówki. Złożoność \(O(n\log n)\) w każdym przypadku (patrz punkt 3).

3. Algorytmy wyszukiwania i sortowania

Wyszukiwanie liniowe

Przeglądanie kolejnych elementów aż do znalezienia szukanego — działa na dowolnej (także nieposortowanej) tablicy. Złożoność: \(O(n)\)

Wyszukiwanie binarne

Wymaga posortowanej tablicy — porównanie ze środkowym elementem, odrzucenie połowy zakresu, powtórzenie. Złożoność: \(O(\log n)\)

Klasyczne algorytmy sortowania

AlgorytmZasada działaniaZłożoność (śr./pesym.)PamięćStabilny?
Sortowanie bąbelkowe (bubble sort) wielokrotne przechodzenie tablicy, zamiana sąsiadów w złej kolejności \(O(n^2)\) / \(O(n^2)\) \(O(1)\) tak
Sortowanie przez wstawianie (insertion sort) wstawianie kolejnego elementu w odpowiednie miejsce w już posortowanej części \(O(n^2)\) / \(O(n^2)\) \(O(1)\) tak
Sortowanie przez wybieranie (selection sort) wybór najmniejszego elementu z nieposortowanej części i zamiana na początek \(O(n^2)\) / \(O(n^2)\) \(O(1)\) nie
Sortowanie szybkie (quicksort) wybór pivota, podział na mniejsze/większe od pivota, rekurencyjne sortowanie części \(O(n\log n)\) / \(O(n^2)\) \(O(\log n)\) nie
Sortowanie przez scalanie (merge sort) dziel i zwyciężaj — podział na pół, rekurencyjne sortowanie, scalanie \(O(n\log n)\) / \(O(n\log n)\) \(O(n)\) tak
Sortowanie przez kopcowanie (heap sort) budowa kopca, wielokrotne wyjmowanie elementu maksymalnego z korzenia \(O(n\log n)\) / \(O(n\log n)\) \(O(1)\) nie
Stabilność sortowania oznacza, że elementy o równych kluczach zachowują względną kolejność z danych wejściowych — ważne np. przy sortowaniu po wielu kryteriach naraz (najpierw po jednym polu, potem stabilnie po drugim).

Kiedy który algorytm?

  • quicksort — zwykle najszybszy w praktyce (dobre stałe), ale pesymistycznie \(O(n^2)\) przy złym wyborze pivota (np. dane już posortowane)
  • merge sort — gwarantowane \(O(n\log n)\) zawsze, kosztem dodatkowej pamięci \(O(n)\); dobry do sortowania list z dowiązaniami i danych zewnętrznych (nie mieszczących się w RAM)
  • proste algorytmy \(O(n^2)\) — sensowne tylko dla małych \(n\) albo prawie posortowanych danych (insertion sort radzi sobie wtedy blisko \(O(n)\))

4. Podstawowe struktury danych

StrukturaCharakterystykaDostępWstaw./Usuń

Lista z dowiązaniami (linked list)węzły połączone wskaźnikami, rozmiar dynamiczny\(O(n)\) (trzeba przejść od początku)\(O(1)\) na znanej pozycji

Stos — operacje

push (dodanie na wierzch), pop (zdjęcie z wierzchu), peek/top (podgląd wierzchołka bez usuwania). Zastosowania: cofanie operacji (undo), wywołania funkcji (stos wywołań), sprawdzanie poprawności nawiasów, algorytmy DFS.

Kolejka — operacje

enqueue (dodanie na koniec), dequeue (zdjęcie z przodu). Zastosowania: obsługa zadań w kolejności zgłoszeń, bufor, algorytmy BFS.

Kolejka priorytetowa — element o najwyższym priorytecie obsługiwany jest jako pierwszy (zwykle implementowana kopcem).

Kopiec (heap) — własność

Kopiec maksymalny: każdy węzeł ma wartość \(\ge\) wartości swoich dzieci (korzeń = element największy). Kopiec minimalny — analogicznie z \(\le\). Zwykle implementowany jako tablica (bez jawnych wskaźników): dziecko elementu o indeksie \(i\) to \(2i+1\) i \(2i+2\).

Lista z dowiązaniami — warianty

jednokierunkowa (każdy węzeł zna tylko następny), dwukierunkowa (zna też poprzedni), cykliczna (ostatni węzeł wskazuje na pierwszy).

5. Tablice z haszowaniem

Struktura pozwalająca na (średnio) \(O(1)\) wyszukiwanie, wstawianie i usuwanie — klucz jest przekształcany funkcją haszującą na indeks tablicy.

Funkcja haszująca

$$h: \text{Klucz} \to \{0, 1, \dots, m-1\}$$

Dobra funkcja haszująca powinna równomiernie rozkładać klucze po całej tablicy (minimalizować kolizje) i być szybka do obliczenia. Przykład prosty: \(h(k) = k \mod m\).

Kolizje

Sytuacja, gdy dwa różne klucze dają ten sam indeks: \(h(k_1) = h(k_2)\), \(k_1 \ne k_2\) — nieuniknione przy dostatecznie dużej liczbie kluczy (paradoks urodzin).

Metody rozwiązywania kolizji

MetodaZasada
Łańcuchowanie (chaining) w każdej "komórce" tablicy trzymana jest lista elementów o tym samym haszu — przy kolizji nowy element dołącza do listy
Adresowanie otwarte (open addressing) przy kolizji szukamy kolejnej wolnej komórki wg ustalonej sekwencji (np. liniowo, kwadratowo, lub double hashing)

Adresowanie otwarte — warianty próbkowania

  • liniowe: sprawdzaj \(h(k), h(k)+1, h(k)+2, \dots \pmod m\) — proste, ale podatne na "grupowanie" (clustering)
  • kwadratowe: \(h(k), h(k)+1^2, h(k)+2^2, \dots\) — redukuje grupowanie
  • podwójne haszowanie: krok wyznaczany drugą funkcją haszującą, najlepiej rozprasza elementy

Współczynnik wypełnienia (load factor)

$$\alpha = \frac{\text{liczba elementów}}{\text{rozmiar tablicy}}$$

Im wyższy \(\alpha\), tym więcej kolizji i wolniejsze operacje — po przekroczeniu progu (np. \(\alpha>0.7\)) tablica zwykle jest powiększana i wszystkie elementy przehaszowywane (rehashing).

Złożoność operacji na tablicy haszującej: średnio \(O(1)\), ale pesymistycznie \(O(n)\) (gdyby wszystkie klucze trafiały do tej samej komórki).

6. Drzewa i ich zastosowania

Podstawowe pojęcia

korzeń (root), węzeł (node), liść (leaf, brak dzieci), rodzic/dziecko, wysokość drzewa (najdłuższa ścieżka od korzenia do liścia).

Drzewo binarne

Każdy węzeł ma co najwyżej dwoje dzieci (lewe i prawe).

Drzewo BST (Binary Search Tree)

Drzewo binarne z własnością porządku: dla każdego węzła — wszystkie wartości w lewym poddrzewie \(<\) wartość węzła \(<\) wszystkie wartości w prawym poddrzewie.

  • wyszukiwanie/wstawianie/usuwanie: \(O(h)\), gdzie \(h\) to wysokość drzewa
  • dla drzewa zbalansowanego: \(h = O(\log n)\) → operacje \(O(\log n)\)
  • dla drzewa zdegenerowanego (np. wstawianie posortowanych danych do zwykłego BST bez balansowania — drzewo staje się listą): \(h = O(n)\) → operacje \(O(n)\)

Drzewa zrównoważone (samobalansujące)

TypCecha
AVL dla każdego węzła różnica wysokości poddrzew \(\le 1\); rotacje po każdej operacji utrzymują balans
Drzewo czerwono-czarne węzły kolorowane cz./cz. wg reguł gwarantujących \(h = O(\log n)\); mniej rotacji niż AVL, używane m.in. w implementacji std::map w C++

Wszystkie operacje na drzewach zrównoważonych: \(O(\log n)\) gwarantowane (nawet w najgorszym przypadku).

B-drzewa

Drzewa o wielu dzieciach na węzeł (nie tylko dwóch) — projektowane pod pamięć zewnętrzną (dyski, bazy danych), gdzie odczyt jednego bloku z dysku jest kosztowny, więc opłaca się przechowywać wiele kluczy w jednym węźle (mniejsza wysokość drzewa = mniej odczytów z dysku).

  • szeroko stosowane w indeksach baz danych i systemach plików
  • wszystkie liście na tej samej głębokości (drzewo idealnie zbalansowane)

Przechodzenie drzewa (traversal)

  • in-order (lewo, korzeń, prawo) — dla BST daje elementy w kolejności rosnącej
  • pre-order (korzeń, lewo, prawo) — przydatne do kopiowania struktury drzewa
  • post-order (lewo, prawo, korzeń) — przydatne do usuwania drzewa (najpierw dzieci)

7. Grafy i algorytmy grafowe

Podstawowe pojęcia

  • graf \(G=(V,E)\) — zbiór wierzchołków \(V\) i krawędzi \(E\)
  • skierowany (digraf) — krawędzie mają kierunek; nieskierowany — krawędzie symetryczne
  • ważony — krawędzie mają przypisaną wagę (koszt/odległość)
  • ścieżka — ciąg wierzchołków połączonych krawędziami; cykl — ścieżka wracająca do punktu startu
  • spójność — graf spójny, jeśli istnieje ścieżka między każdą parą wierzchołków

Reprezentacje grafu

ReprezentacjaOpisPamięćSprawdzenie krawędzi (u,v)
Macierz sąsiedztwatablica \(n \times n\), 1 (lub waga) jeśli krawędź istnieje\(O(n^2)\)\(O(1)\)
Lista sąsiedztwadla każdego wierzchołka lista jego sąsiadów\(O(n+m)\)\(O(\deg(u))\)

(gdzie \(n\) = liczba wierzchołków, \(m\) = liczba krawędzi; lista sąsiedztwa jest efektywniejsza pamięciowo dla grafów rzadkich — czyli większości grafów spotykanych w praktyce)

Przeszukiwanie grafu

  • BFS (przeszukiwanie wszerz) — używa kolejki (FIFO), odwiedza wierzchołki warstwami wg odległości od startu; znajduje najkrótszą ścieżkę w grafie nieważonym; złożoność \(O(n+m)\)
  • DFS (przeszukiwanie w głąb) — używa stosu (lub rekurencji), zagłębia się maksymalnie w jedną gałąź przed cofnięciem; złożoność \(O(n+m)\); zastosowania: wykrywanie cykli, sortowanie topologiczne, wyznaczanie spójnych składowych

Najkrótsze ścieżki

AlgorytmZastosowanieZłożoność
BFS najkrótsza ścieżka w grafie nieważonym \(O(n+m)\)
Dijkstra najkrótsze ścieżki z jednego źródła, wagi nieujemne \(O((n+m)\log n)\) z kopcem
Bellman-Ford najkrótsze ścieżki z jednego źródła, dopuszcza wagi ujemne (wykrywa też cykle ujemne) \(O(n \cdot m)\)
Floyd-Warshall najkrótsze ścieżki między wszystkimi parami wierzchołków \(O(n^3)\)

Algorytm Dijkstry — idea

  1. ustaw odległość źródła na 0, pozostałych na \(\infty\)
  2. wybierz nieodwiedzony wierzchołek o najmniejszej znanej odległości (kolejka priorytetowa/kopiec)
  3. zrelaksuj (zaktualizuj) odległości jego sąsiadów, jeśli znaleziono krótszą ścieżkę przez niego
  4. oznacz wierzchołek jako odwiedzony, powtarzaj aż wszystkie wierzchołki odwiedzone
Dijkstra nie działa poprawnie przy ujemnych wagach krawędzi (może dać błędny wynik) — wtedy trzeba użyć Bellmana-Forda.

Minimalne drzewo rozpinające (MST)

Podzbiór krawędzi łączący wszystkie wierzchołki przy minimalnej sumie wag, bez cykli. Algorytmy: Kruskala (sortuj krawędzie rosnąco, dodawaj jeśli nie tworzy cyklu — struktura zbiorów rozłącznych) i Prima (rozbudowuj drzewo od jednego wierzchołka, zawsze dodając najtańszą krawędź wychodzącą z aktualnego drzewa).

8. Programowanie dynamiczne

Technika rozwiązywania problemów przez podział na nakładające się podproblemy (overlapping subproblems) i zapamiętywanie ich wyników, żeby nie liczyć tego samego wielokrotnie — w przeciwieństwie do naiwnej rekurencji (np. Fibonacci z punktu 2, gdzie \(fib(3)\) liczy się wielokrotnie w różnych gałęziach drzewa wywołań).

Warunek stosowalności

  • optymalna podstruktura — rozwiązanie problemu da się zbudować z optymalnych rozwiązań podproblemów
  • nakładające się podproblemy — te same podproblemy pojawiają się wielokrotnie

Dwa podejścia

PodejścieZasada
Memoizacja (top-down) zwykła rekurencja + tablica/mapa zapamiętująca już policzone wyniki (jeśli wynik dla danych argumentów już istnieje, zwróć go zamiast liczyć ponownie)
Tabulacja (bottom-up) iteracyjne wypełnianie tablicy wyników od najmniejszych podproblemów do właściwego, bez rekurencji

Przykład — Fibonacci z memoizacją

int memo[100] = {0};

int fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];   // wynik już policzony
    return memo[n] = fib(n-1) + fib(n-2);
}

Złożoność spada z \(O(2^n)\) (naiwna rekurencja) do \(O(n)\).

Klasyczne problemy DP

  • problem plecakowy (knapsack) — wybór podzbioru przedmiotów o maksymalnej wartości przy ograniczonej pojemności
  • najdłuższy wspólny podciąg (LCS) — dla dwóch ciągów znaków
  • najdłuższy rosnący podciąg (LIS)
  • problem zmiany monet (coin change) — minimalna liczba monet dającą daną sumę
Typowe pytanie: rozróżnij, czy dany problem nadaje się do DP (ma optymalną podstrukturę i nakładające się podproblemy), czy wystarczy podejście zachłanne (patrz punkt 9).

9. Algorytmy zachłanne (greedy)

Podejmowanie w każdym kroku decyzji lokalnie najlepszej (bez oglądania się na przyszłe konsekwencje), z nadzieją, że suma lokalnie optymalnych wyborów da globalnie optymalne rozwiązanie.

Kiedy działa poprawnie

Tylko gdy problem ma własność wyboru zachłannego — lokalnie optymalny wybór w danym kroku prowadzi do globalnie optymalnego rozwiązania. Nie każdy problem to spełnia!

Przykłady, gdzie greedy działa

  • algorytm Kruskala/Prima (minimalne drzewo rozpinające, patrz punkt 7) — zawsze wybieraj najtańszą dostępną krawędź
  • algorytm Dijkstry (patrz punkt 7) — zawsze przetwarzaj najbliższy nieodwiedzony wierzchołek
  • kodowanie Huffmana (patrz przedmiot Teoretyczne podstawy informatyki) — zawsze łącz dwa węzły o najmniejszej wadze
  • problem wydawania reszty — dla "wygodnych" nominałów (np. 1,5,10,25...) zachłanne wybieranie największego możliwego nominału daje optymalny wynik
  • problem wyboru zajęć (activity selection) — sortuj wg czasu zakończenia, wybieraj kolejne niekolidujące

Przykład, gdzie greedy zawodzi

Problem plecakowy 0/1 (nie da się wziąć ułamka przedmiotu) — wybieranie zachłannie przedmiotów o najlepszym stosunku wartość/waga nie zawsze daje optymalne rozwiązanie; tu potrzeba DP.

Greedy jest zwykle znacznie szybszy niż DP (nie trzeba przechowywać/przeglądać wszystkich podproblemów), ale wymaga dowodu poprawności dla konkretnego problemu — "wydaje się słuszne" nie wystarczy.

10. Zbiory rozłączne (Union-Find)

Struktura danych do zarządzania podziałem elementów na rozłączne grupy (zbiory), z dwiema głównymi operacjami:

  • Find(x) — zwraca reprezentanta (etykietę) zbioru, do którego należy element \(x\)
  • Union(x,y) — łączy zbiory zawierające \(x\) i \(y\) w jeden

Implementacja — las drzew (forest)

Każdy zbiór to drzewo; każdy element wskazuje na swojego rodzica, korzeń wskazuje sam na siebie (reprezentant zbioru).

Optymalizacje

  • kompresja ścieżek (path compression) — podczas Find, każdy odwiedzony węzeł na ścieżce podłącza się bezpośrednio pod korzeń, spłaszczając drzewo na przyszłość
  • łączenie wg rangi/rozmiaru (union by rank/size) — przy Union mniejsze/płytsze drzewo podłącza się pod większe, zamiast odwrotnie

Z obiema optymalizacjami złożoność operacji jest praktycznie stała: \(O(\alpha(n))\), gdzie \(\alpha\) to odwrotna funkcja Ackermanna (rośnie tak wolno, że dla wszystkich praktycznych \(n\) jest \(\le 4\)).

Zastosowania

  • algorytm Kruskala (patrz punkt 7) — sprawdzanie, czy dodanie krawędzi utworzyłoby cykl (czy oba wierzchołki są już w tym samym zbiorze)
  • wykrywanie spójnych składowych grafu
  • algorytmy dotyczące dynamicznej łączności (czy dwa elementy są already połączone jakąś ścieżką operacji)

11. Sortowanie nieporównawcze

Sortowania, które nie opierają się na porównywaniu par elementów (stąd mogą przełamać teoretyczną dolną granicę \(\Omega(n\log n)\) dla sortowań porównawczych) — kosztem dodatkowych założeń o danych (np. że to liczby całkowite z ograniczonego zakresu).

Sortowanie przez zliczanie (counting sort)

  1. policz, ile razy występuje każda wartość z zakresu \([0,k]\) (tablica liczników)
  2. przelicz sumy skumulowane liczników (pozycja, na której powinien skończyć się dany klucz w wyniku)
  3. przepisz elementy na właściwe pozycje w tablicy wynikowej

Złożoność: \(O(n+k)\), gdzie \(k\) to rozpiętość wartości. Dobre, gdy \(k = O(n)\) (mały zakres wartości), fatalne przy dużym rozrzucie liczb (duże zużycie pamięci na tablicę liczników).

Sortowanie kubełkowe (bucket sort)

Rozrzuć elementy do "kubełków" (przedziałów wartości), posortuj każdy kubełek osobno (np. insertion sortem), połącz wyniki. Dobre dla danych równomiernie rozłożonych w znanym przedziale (np. liczb zmiennoprzecinkowych z \([0,1)\)). Średnia złożoność: \(O(n+k)\).

Sortowanie pozycyjne (radix sort)

Sortuj kolejno po cyfrach/bajtach klucza (od najmniej znaczącej do najbardziej znaczącej), używając stabilnego sortowania pomocniczego (zwykle counting sort) na każdym etapie. Złożoność: \(O(d\cdot(n+k))\), gdzie \(d\) to liczba cyfr, \(k\) to podstawa systemu liczbowego.

Te algorytmy omijają dolne ograniczenie \(\Omega(n\log n)\) obowiązujące dla sortowań opartych na porównaniach, ale robią to kosztem założeń o strukturze danych (np. że są to liczby całkowite z ograniczonego zakresu) — nie da się nimi posortować dowolnych, niezależnie porównywalnych obiektów.

12. Drzewo TRIE

Drzewo wyszukiwania przechowujące ciągi znaków (stringi), gdzie każda ścieżka od korzenia reprezentuje prefiks jakiegoś słowa — węzły dzielą wspólne prefiksy między sobą.

Struktura

  • każdy węzeł ma do 26 (lub więcej, zależnie od alfabetu) dzieci — po jednym na możliwy kolejny znak
  • węzeł oznaczony jako "koniec słowa" wskazuje, że ścieżka od korzenia do niego stanowi kompletne słowo w zbiorze

Przykład — wstawione słowa: "kot", "kotek", "koc"

root
 └─ k
     └─ o
         ├─ t (koniec słowa: "kot")
         │   └─ e
         │       └─ k (koniec słowa: "kotek")
         └─ c (koniec słowa: "koc")

Wspólny prefiks "ko" jest przechowywany tylko raz, mimo że pojawia się w trzech słowach.

Operacje i złożoność

  • wstawianie/wyszukiwanie słowa o długości \(m\): \(O(m)\) — niezależne od liczby słów w strukturze!
  • wyszukiwanie wszystkich słów o danym prefiksie — bardzo wydajne (od razu "schodzisz" do odpowiedniego węzła)

Zastosowania

autouzupełnianie (podpowiedzi wyszukiwarki), słowniki ortograficzne, routing IP (najdłuższy pasujący prefiks), sprawdzanie unikalności/duplikatów prefiksów w dużych zbiorach tekstu.

Koszt: zużycie pamięci może być duże (każdy węzeł potencjalnie ma wiele wskaźników na dzieci) — kompromis między szybkością operacji a zużyciem pamięci względem np. tablicy haszującej przechowującej całe stringi.
