Języki hipertekstowe i tworzenie stron WWW

1. Kaskadowe arkusze stylów (CSS) — rodzaje, priorytety, zasięg

Rodzaje (sposoby dołączenia) stylów

  1. styl inline — bezpośrednio w atrybucie style elementu: 
    <p style="color: red;">Tekst</p>
  2. styl wewnętrzny — w sekcji <head> dokumentu: 
    <style>
  p { color: red; }
</style>
  3. styl zewnętrzny — osobny plik .css dołączony przez <link>: 
    <link rel="stylesheet" href="styl.css">

Styl zewnętrzny jest najbardziej praktyczny (jeden plik dla wielu podstron, cache przeglądarki, czytelność kodu).

Priorytety (specyficzność selektorów)

Gdy kilka reguł CSS dotyczy tego samego elementu, wygrywa reguła o wyższej specyficzności. Kolejność od najsłabszej do najsilniejszej:

  1. selektor znacznika (np. p)
  2. selektor klasy, atrybutu, pseudoklasy (np. .klasa, [type], :hover)
  3. selektor identyfikatora (np. #id)
  4. styl inline (style="...")
  5. !important — nadpisuje wszystko powyższe (używać oszczędnie!)
Przy równej specyficzności wygrywa reguła zdefiniowana później w kodzie ("kaskadowość" — stąd nazwa CSS: Cascading Style Sheets).

Zasięg (dziedziczenie)

  • niektóre właściwości dziedziczą się automatycznie z elementu nadrzędnego na potomków (np. color, font-family)
  • inne nie dziedziczą się domyślnie (np. margin, border, width) — trzeba by wymusić słowem kluczowym inherit

2. Znaczniki semantyczne HTML5

Znaczniki, które opisują znaczenie (rolę) fragmentu strony, a nie tylko jego wygląd — ułatwiają dostępność (screen readery), SEO i czytelność kodu, w przeciwieństwie do samego <div>, który nic nie mówi o roli elementu.

ZnacznikZnaczenie
<header>nagłówek strony lub sekcji (logo, nawigacja, tytuł)
<nav>blok nawigacyjny (menu, linki)
<main>główna, unikalna treść strony (tylko jeden na stronę)
<article>samodzielna treść, np. wpis na blogu, artykuł prasowy
<section>tematyczna sekcja treści (zwykle z nagłówkiem)
<aside>treść poboczna, np. panel boczny, reklama, powiązane linki
<footer>stopka strony/sekcji (dane kontaktowe, prawa autorskie)
<figure> + <figcaption>obraz/ilustracja z podpisem
<time>data/godzina, czytelna maszynowo (datetime)

Przykładowa struktura semantyczna

<body>
  <header><nav>...</nav></header>
  <main>
    <article>
      <section>...</section>
    </article>
    <aside>...</aside>
  </main>
  <footer>...</footer>
</body>
Przed HTML5 wszystko budowano na <div> z klasami typu class="header" — semantyczne znaczniki to standaryzacja tego podejścia wprost w języku.

3. Funkcjonalności realizowane przez języki backendowe (np. PHP)

Kod backendowy wykonuje się na serwerze, zanim wynik (gotowy HTML) trafi do przeglądarki użytkownika.

Typowe zastosowania

  • obsługa formularzy — odbiór danych ($_POST, $_GET), walidacja, zapis do bazy
  • komunikacja z bazą danych — pobieranie/zapisywanie danych (np. lista produktów, logowanie użytkownika)
  • autoryzacja i sesje — logowanie, sprawdzanie uprawnień, przechowywanie stanu użytkownika ($_SESSION, ciasteczka)
  • generowanie dynamicznej treści — inna zawartość strony w zależności od danych (np. spersonalizowana strona po zalogowaniu)
  • przetwarzanie plików — upload zdjęć, generowanie PDF, eksport danych (CSV, Excel)
  • logika biznesowa — obliczenia, walidacja reguł, które nie powinny być widoczne/edytowalne po stronie klienta (np. ceny, rabaty)
  • API / komunikacja z innymi systemami — wywołania do zewnętrznych usług, zwracanie danych w JSON
Kluczowa zasada: wszystko, co dotyczy bezpieczeństwa i poufnych danych (hasła, klucze API, logika biznesowa, walidacja krytyczna) musi być po stronie backendu — kod frontendowy (JS) jest zawsze widoczny i edytowalny przez użytkownika w przeglądarce.

4. Funkcjonalności realizowane przez języki frontendowe (np. JavaScript)

Kod frontendowy wykonuje się w przeglądarce użytkownika, już po dostarczeniu strony — pozwala na interakcję bez przeładowywania całej strony.

Typowe zastosowania

  • manipulacja DOM — dynamiczna zmiana treści/wyglądu strony bez przeładowania (np. rozwijane menu, zakładki, modale)
  • walidacja formularzy po stronie klienta — natychmiastowy feedback dla użytkownika (np. czy pole email ma poprawny format), zanim dane w ogóle trafią na serwer
  • obsługa zdarzeń — reakcja na kliknięcia, ruch myszy, wpisywanie tekstu (addEventListener)
  • AJAX / fetch — pobieranie/wysyłanie danych do serwera w tle, bez przeładowania strony (np. czat, podpowiedzi wyszukiwania, "wczytaj więcej")
  • animacje i efekty wizualne — płynne przejścia, karuzele, efekty przy scrollowaniu
  • przechowywanie danych po stronie klienta — localStorage, sessionStorage, ciasteczka (np. zapamiętanie motywu ciemny/jasny)
  • walidacja i logika interfejsu — np. dynamiczne przeliczanie sumy koszyka bez odpytywania serwera
Walidacja frontendowa poprawia komfort użytkownika (szybki feedback), ale nigdy nie zastępuje walidacji backendowej — użytkownik może wyłączyć JS albo wysłać żądanie z pominięciem przeglądarki (np. przez curl).

Różnica potomek vs dziecko — przykład

<div>
  <p>A</p>              <!-- bezpośrednie dziecko div -->
  <span><p>B</p></span>  <!-- p jest wnukiem div, nie dzieckiem -->
</div>
  • div p — zaznaczy oba paragrafy (A i B)
  • div > p — zaznaczy tylko paragraf A

Przydatne pseudoklasy

:first-child, :last-child, :nth-child(n), :not(selektor), :focus, :checked, :disabled

6. Strony responsywne

Strona responsywna dostosowuje układ i wygląd do różnych rozmiarów ekranu (telefon, tablet, desktop) bez tworzenia osobnych wersji strony.

Meta viewport

Konieczny tag, żeby responsywność działała poprawnie na urządzeniach mobilnych:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Media queries

Reguły CSS stosowane tylko przy spełnieniu warunku dotyczącego ekranu (szerokość, orientacja itd.):

/* domyślnie: styl dla desktopu */
.kontener { display: flex; }

@media (max-width: 768px) {
    /* styl stosowany tylko gdy szerokość ekranu ≤ 768px */
    .kontener { flex-direction: column; }
}

Jednostki względne

  • % — względem rodzica
  • em — względem rozmiaru czcionki rodzica
  • rem — względem rozmiaru czcionki elementu głównego (html)
  • vw, vh — względem szerokości/wysokości okna przeglądarki (1vw = 1% szerokości ekranu)

Layout responsywny

  • Flexbox — jednowymiarowe układy (rząd lub kolumna), elastyczne rozmieszczanie elementów
  • CSS Grid — dwuwymiarowe układy (wiersze i kolumny naraz), lepszy do całych layoutów strony
  • obrazy responsywne — max-width: 100%; żeby obraz nie wychodził poza kontener

Podejście mobile-first

Projektowanie stylów bazowych dla ekranu mobilnego, a media queries (min-width) dodają/rozszerzają układ dla większych ekranów — uznawane za lepszą praktykę niż odwrotne podejście (desktop-first z max-width).

7. Funkcje PHP do współpracy z bazami danych

MySQLi (rozszerzenie proceduralne/obiektowe)

$polaczenie = mysqli_connect("localhost", "user", "haslo", "baza");

$wynik = mysqli_query($polaczenie, "SELECT * FROM produkty");
while ($wiersz = mysqli_fetch_assoc($wynik)) {
    echo $wiersz['nazwa'];
}

mysqli_close($polaczenie);

PDO (PHP Data Objects) — nowocześniejsze, zalecane podejście

$pdo = new PDO("mysql:host=localhost;dbname=baza", "user", "haslo");

$stmt = $pdo->prepare("SELECT * FROM produkty WHERE cena > ?");
$stmt->execute([100]);

foreach ($stmt->fetchAll(PDO::FETCH_ASSOC) as $wiersz) {
    echo $wiersz['nazwa'];
}

Zapytania przygotowane (prepared statements)

Kluczowe dla bezpieczeństwa — parametry (? lub :nazwa) są wiązane osobno, a nie wklejane bezpośrednio do zapytania SQL:

$stmt = $pdo->prepare("INSERT INTO uzytkownicy (login, haslo) VALUES (:login, :haslo)");
$stmt->execute(['login' => $login, 'haslo' => password_hash($haslo, PASSWORD_DEFAULT)]);
SQL injection — jeśli dane od użytkownika wkleja się bezpośrednio do zapytania (np. "SELECT * FROM users WHERE login='".$login."'"), atakujący może wstrzyknąć własny kod SQL. Zapytania przygotowane (prepared statements) są podstawową ochroną przed tym atakiem.

Najważniejsze funkcje

FunkcjaZastosowanie
mysqli_connect() / new PDO()nawiązanie połączenia z bazą
mysqli_query() / ->query()wykonanie zapytania SQL
prepare() + execute()zapytanie przygotowane (bezpieczne, z parametrami)
fetch_assoc() / fetchAll()pobranie wyniku zapytania jako tablicy asocjacyjnej
mysqli_close()zamknięcie połączenia
lastInsertId()pobranie ID ostatnio wstawionego wiersza

8. Protokół HTTP

Protokół komunikacji między przeglądarką (klientem) a serwerem — działa na zasadzie żądanie → odpowiedź (request/response), bezstanowo (każde żądanie jest niezależne, serwer sam z siebie nie pamięta poprzednich żądań — stąd potrzeba sesji/ciasteczek).

Struktura żądania (request)

GET /produkty?kategoria=buty HTTP/1.1
Host: sklep.pl
User-Agent: Mozilla/5.0...
Cookie: sesja=abc123

Metody HTTP

MetodaZastosowanie
GETpobranie danych; parametry w URL; nie powinna zmieniać stanu serwera
POSTwysłanie danych (np. formularz), zwykle tworzy nowy zasób; dane w ciele żądania, nie w URL
PUTaktualizacja/zastąpienie całego istniejącego zasobu
PATCHczęściowa aktualizacja zasobu
DELETEusunięcie zasobu

Kody odpowiedzi (status)

ZakresZnaczeniePrzykłady
2xxsukces200 OK, 201 Created, 204 No Content
3xxprzekierowanie301 Moved Permanently, 302 Found
4xxbłąd po stronie klienta400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found
5xxbłąd po stronie serwera500 Internal Server Error, 503 Service Unavailable

Nagłówki (headers)

Dodatkowe metadane żądania/odpowiedzi, np. Content-Type (typ przesyłanych danych: text/html, application/json), Set-Cookie, Authorization.

HTTPS to HTTP szyfrowane protokołem TLS/SSL — chroni przesyłane dane (np. hasła) przed podsłuchaniem po drodze między klientem a serwerem.

9. Model pudełkowy CSS (box model)

Każdy element HTML jest traktowany jako prostokątne "pudełko" złożone z czterech warstw (od środka na zewnątrz):

  1. content — właściwa treść elementu (tekst, obraz), jej rozmiar to width/height
  2. padding — wewnętrzny odstęp między treścią a krawędzią (border)
  3. border — obramowanie elementu
  4. margin — zewnętrzny odstęp między elementem a sąsiednimi elementami

Domyślne obliczanie szerokości (box-sizing: content-box)

$$\text{całkowita szerokość} = \text{width} + \text{padding-left} + \text{padding-right} + \text{border-left} + \text{border-right}$$

(margin nie wlicza się do "szerokości elementu" — to odstęp na zewnątrz)

box-sizing: border-box

Popularna alternatywa — width/height obejmuje już padding i border, więc podana szerokość to całkowita szerokość widocznego pudełka (łatwiej liczyć layout):

* { box-sizing: border-box; }   /* częsty reset na początku arkusza CSS */

Przykład

div {
    width: 200px;
    padding: 10px;
    border: 2px solid black;
    margin: 5px;
}
/* content-box: całkowita szerokość = 200+10+10+2+2 = 224px */
/* border-box:   całkowita szerokość = dokładnie 200px */
Klasyczny błąd początkujących: dodanie padding do elementu o ustalonej szerokości "rozsadza" layout — border-box rozwiązuje ten problem.

10. Formularze HTML

Podstawowa struktura

<form action="przetworz.php" method="POST">
    <label for="email">E-mail:</label>
    <input type="email" id="email" name="email" required>

    <input type="submit" value="Wyślij">
</form>
  • action — adres, na który wysyłane są dane formularza
  • method — GET (dane w URL) lub POST (dane w ciele żądania, np. do logowania/przesyłania plików)

Typy pola <input>

TypZastosowanie
textzwykły tekst jednoliniowy
passwordtekst maskowany kropkami
emailtekst z wbudowaną walidacją formatu e-mail
numberwartość liczbowa (ze strzałkami do zmiany)
checkboxpole wyboru (wiele opcji naraz)
radioprzycisk wyboru (jedna opcja z grupy o tej samej name)
datewybór daty (kalendarz w przeglądarce)
filewybór pliku do wysłania
hiddenukryte pole, np. token CSRF, przesyłane niewidocznie dla użytkownika

Atrybuty walidacyjne (HTML5)

  • required — pole obowiązkowe
  • pattern="regex" — wartość musi pasować do wyrażenia regularnego
  • min, max — zakres dla liczb/dat
  • minlength, maxlength — długość tekstu
Walidacja HTML5 działa tylko po stronie przeglądarki — jak w punkcie 4, to nie zwalnia z konieczności walidacji tych samych danych po stronie backendu (użytkownik może ją obejść).

Inne elementy formularza

<textarea> (wieloliniowy tekst), <select> + <option> (lista rozwijana), <fieldset> + <legend> (grupowanie powiązanych pól).

11. DOM (Document Object Model)

Reprezentacja dokumentu HTML jako drzewa obiektów w pamięci przeglądarki — JavaScript operuje właśnie na tym drzewie, a nie bezpośrednio na tekście HTML.

Struktura drzewa

<html>
  <body>
    <h1>Tytuł</h1>
    <p>Tekst</p>
  </body>
</html>

Każdy znacznik staje się węzłem (node) drzewa: document → html → body → {h1, p}. Węzły mogą być elementami, tekstem, atrybutami itd.

Podstawowe metody dostępu do elementów

document.getElementById("id")
document.getElementsByClassName("klasa")
document.querySelector(".klasa")     // pierwszy pasujący element
document.querySelectorAll("p")       // wszystkie pasujące elementy

Manipulacja elementami

let el = document.querySelector("#tytul");
el.textContent = "Nowy tekst";     // zmiana treści
el.style.color = "red";            // zmiana stylu
el.classList.add("aktywny");       // dodanie klasy CSS
el.remove();                       // usunięcie elementu z drzewa

let nowy = document.createElement("p");
document.body.appendChild(nowy);   // dodanie nowego elementu do drzewa

Relacje między węzłami

parentNode (rodzic), childNodes / children (dzieci), nextElementSibling / previousElementSibling (rodzeństwo).

DOM to most między statycznym HTML a dynamicznym JavaScriptem — dzięki drzewiastej reprezentacji, JS może w locie odczytywać i zmieniać strukturę oraz treść strony bez przeładowania.
